# 微信小店AI客服系统

**让 AI 全程接待，也可以随时人工介入，让对话在微信与客服工作台之间流转。**

连接微信小店客服回调、微语（Bytedesk）工作台与兼容 OpenAI 格式的 AI 对话接口。支持多店铺配置、用户与 AI 消息同步、人工接管、双向图片，以及 SQLite 持久化消息任务。

本仓库只发布通用程序与模拟测试。部署者使用自己的平台账号和凭据；仓库不附带店铺配置、客户数据、聊天记录、知识库或模型密钥。

## 项目优势

| 优势 | 带来的价值 |
| --- | --- |
| AI 接待与人工协作 | AI 处理文字咨询，客服在微语回复即可接管当前会话；程序在 AI 发送前复查接管状态，减少双方同时回复的情况。 |
| 人工超时自动接回 | 从第一条未获人工回复的用户消息起等待 180 秒，之后可由 AI 接回；用户连续补充不会延长截止时间。 |
| 主动交回 AI | 客服可发送 `/交回AI` 或 `/ai` 释放会话；指令不会转发给微信用户，没有待回复消息时不额外发言。 |
| 复用现有客服工作台 | 用户消息和 AI 回复同步到微语，人工在同一工作台查看与回复，减少额外建设客服界面的工作。 |
| 多店铺统一接入 | 每店独立配置微信凭据、微语地址及组织/客服标识，按店铺路由并保存会话映射，方便自有多店统一维护。 |
| 消息任务可恢复 | 回调消息先写入 SQLite，再确认接收；后台可恢复未完成任务，降低进程重启或内存队列拥堵造成的任务丢失风险。 |
| 重试与顺序控制 | 持久任务记录尝试次数和错误状态，采用退避重试；同会话的前序失败任务会阻止后续同类任务越过它。 |
| 减少重复处理与转发 | 入站任务按来源标识去重，人工出站复用稳定请求 ID；AI 镜像、内部备注与系统消息不作为人工公开回复转发。 |
| 图片双向收发 | 用户图片归档到微语供人工查看，客服图片经微信上传接口回发，支持图片下载、上传与发送过程中的失败恢复。 |
| 撤回状态有区分 | 发送前检查原消息状态，图片传输后再次检查；区分发送前取消、发送结果未知，以及仅微语侧撤回。 |
| 媒体与凭据边界明确 | 图片下载限制来源、重定向、大小及文件头格式；下载不携带业务鉴权头，真实凭据从部署环境加载。 |
| 方便自部署与二次开发 | Python 模块按配置、平台适配、会话、媒体和任务拆分；提供模拟测试、GitHub 自动检查与 MIT 许可。 |

这些优势对应当前源码中的机制。实际响应速度、平台去重效果、店铺权限与微语版本兼容性需要在部署环境验证；本项目未提供业务量、节省成本或转化率的实测承诺。

## 适合哪些场景

- **已有微信小店和微语工作台，希望加入 AI 接待**：保留人工工作台，通过桥接层接入 AI 回复与人工切换。
- **自有多店铺共用一套维护方式**：统一维护程序，各店使用自己的凭据、组织和会话映射。
- **常见咨询先由 AI 帮助，复杂问题由人工处理**：利用人工回复接管、主动释放与超时接回机制协调接待。
- **客服需要查看用户图片，并把处理图片发回微信**：使用已接入的图片归档和双向发送链路。
- **希望掌握部署位置并继续开发业务功能**：自行部署桥接、Redis 和任务数据库，在清晰的模块接口上扩展。

接入需使用部署者有权调用的应用和店铺，并遵守微信、微语及模型服务的现行规则；开源许可不授予平台接口权限。

## AI 与人工如何协作

| 场景 | 当前行为 |
| --- | --- |
| 会话未被人工接管 | 用户消息同步到微语，AI 生成文字回复并回发微信。 |
| 人工在工作台回复 | 该用户会话进入人工接管；其他会话继续按各自状态处理。 |
| AI 生成中或同步回复时，人工介入 | 在 AI 回发前重新收集人工回复并检查接管状态，取消尚未发送的 AI 回复。 |
| 人工接管后，用户发来新消息 | 先同步工作台，从第一条待回复消息开始计时；后续补充不重新计时。 |
| 等待期间人工回复 | 清除本轮等待计时，保持人工接管；后续新问题重新开始等待。 |
| 待回复消息超过 180 秒 | 复查人工回复及会话版本，符合条件时将待回复内容合并为一个 AI 接回任务。 |
| 客服发送 `/交回AI` 或 `/ai` | 主动释放；有待回复内容才继续接待，指令本身不发给用户。 |

接管状态与等待起点保存在 SQLite 中；会话版本检查用于避免过期的超时任务覆盖更新后的人工状态。超时接回会合并待回复文字，这不代表已实现完整历史记忆或跨轮知识检索。

## 消息可靠性设计

### 先保存任务，再确认接收

微信回调完成验签、解密和店铺接收方检查后，先写入本地任务数据库，再返回确认。AI 调用与消息转发由后台处理，缩短回调等待业务处理的时间；如果入站任务无法保存，接口返回失败，让平台有机会重试。

内存队列只用于唤醒后台。进程重新启动后，后台仍可从数据库查找待处理、待重试及租约到期的任务。数据库需要持久存储与备份，这一机制不能替代存储本身的可靠性保障。

### 失败保留状态，重试保留原始发送内容

任务记录发送状态、尝试次数、下次重试时间及结果。人工出站在重试中复用已完成的上传结果和稳定请求 ID；发现原消息内容改变时，停止沿用旧任务发送，交由人工核实。平台是否最终去重仍以实际接口能力为准。

不可恢复错误或达到重试上限的任务保留失败状态。同会话同类后续任务等待前序任务处理，减少乱序；任务筛选按会话区分，但当前实现不承诺多会话并行吞吐或多实例部署能力。

### 识别消息来源，尊重撤回与未知结果

程序区分用户、AI 镜像、真实人工、内部备注和系统事件，降低 AI 回复被再次当作人工回复转发、误触发接管的风险。人工消息发送前还会按消息、会话与组织核对当前记录。

图片传输期间发生撤回，会在实际发送前再次检查；已接受或结果未知的微信发送单独记录，避免把工作台撤回描述为微信已经撤回。发送结果与错误保存在任务日志中，常规发送状态不额外插入聊天时间线。

## 当前消息能力

| 消息或功能 | 当前支持范围 |
| --- | --- |
| 用户文字 | 同步微语、调用 AI、文字回发。 |
| 用户图片 | 下载校验、归档微语并作为图片展示；AI 当前只获得图片占位说明。 |
| 客服文字、图片 | 从微语读取公开人工回复，进入持久化发送流程并回发微信。 |
| 语音 | 使用平台已提供的转写文字；未提供转写时使用说明文字，不包含独立语音识别服务。 |
| 文件、视频 | 当前主流程转换为说明文字，尚无与图片相同的完整附件收发链路。 |
| 商品卡片、订单卡片 | 提取卡片标识形成文字上下文，不等于已查询商品详情或订单状态。 |
| 引用消息、服务评价 | 规整为可供 AI 处理的文字。 |
| 售后更新及系统事件 | 作为内部事件同步，避免误当成用户咨询触发自动回复；缺少单号时明确标记信息不足。 |
| 文件、视频、商品和订单发送接口 | 客户端提供封装方法；完整工作台转发及业务查询流程仍需另行接入。 |

## 自部署与扩展价值

**公开代码与私有配置分离。** 微信凭据、微语令牌和数据库连接从环境加载；公开版本使用独立历史、文件白名单和占位配置。可以公开通用实现，同时独立维护部署资料。使用外部 AI 服务时，请求内容仍会按实际配置发往该服务。

**复用现有服务，桥接职责集中。** Redis 管理微信令牌缓存与会话映射，SQLite 管理本地任务，微语负责工作台与对话服务。令牌按应用缓存并通过 Redis 刷新锁协调刷新，减少重复请求。AI 与微信 API 的适配分别集中在独立模块，便于核对接口及调整服务配置。

**模块边界清楚。** 不同职责可以分别阅读、测试和扩展：

| 模块 | 职责 |
| --- | --- |
| `main.py` / `crypto.py` | HTTP 回调、签名检查与消息加解密 |
| `config.py` / `store.py` | 多店铺配置、Redis 缓存与会话映射 |
| `conversation.py` | AI/人工接管、待回复计时与恢复 |
| `delivery.py` / `delivery_service.py` | 持久化任务、人工出站、重试所需状态与撤回处理 |
| `weiyu.py` / `wxstore.py` | 微语与微信平台接口适配 |
| `media.py` | 可信图片来源、逐跳重定向检查、大小限制及 PNG/JPEG/GIF/WebP 文件头检查 |
| `worker.py` | 后台任务、人工回复采集与流程协调 |

**关键场景可在没有真实账号时验证。** 当前提供 26 项模拟测试，覆盖人工介入竞争、180 秒恢复规则、重启恢复、图片双向传输、稳定请求 ID、撤回及媒体来源限制。测试和文件白名单检查已接入 GitHub Actions。MIT 许可允许按许可证条款修改与分发；外部服务的许可、费用和接入要求独立适用。

## 工作方式

```text
微信小店 HTTPS 回调
  → FastAPI 验签 / 解密
  → SQLite 任务日志 / 异步 worker
  → 微语工作台 / AI 对话接口
  → 微信小店消息 API
```

Redis 用于令牌缓存、去重及会话映射；微语维护工作台消息。人工回复后暂停该会话的 AI；出现待回复用户消息后，180 秒无人工回复可恢复 AI，也支持 `/交回AI` 指令。

## 本地安装

需要 Python 3.10+、Redis，以及由部署者独立安装并配置的微语服务及 MySQL。微语 API 和表结构可能随版本变化，需要在测试环境核实兼容性。

```bash
git clone https://github.com/NostalgiaU/customer-service-system-public.git
cd customer-service-system-public
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

在本机编辑 `.env`，填写各店铺的 `SHOPS_JSON`、Redis 地址与微语数据库连接信息。样例中的字符串均为占位符，不能直接连接真实店铺。AI 提供商的 API Key 在微语服务端独立配置，不写入本仓库。

本地测试 Redis 可绑定回环地址：

```bash
docker run -d --name wx-cs-redis -p 127.0.0.1:6379:6379 redis:7-alpine
uvicorn main:app --host 127.0.0.1 --port 8000 --no-access-log
```

通过 HTTPS 反向代理发布 `/wxstore/{slug}/webhook`，在对应店铺配置 Token、EncodingAESKey 和安全模式。`slug` 为 `shop_user_name` 去掉 `gh_` 前缀后转小写的值。反向代理日志应去掉回调查询参数。

微语需提供 `POST /api/v1/chat/completions` 及程序使用的访客、消息和订阅接口。`weiyu_tenant_token` 的登录身份与目标客服身份需要匹配。请先使用测试店完成收发、人工接管、图片和重启恢复验证，并核对平台当前接口权限与接入规则。

## 配置

| 变量 | 用途 |
| --- | --- |
| `SHOPS_JSON` | 每家店铺的凭据、微语地址及客服标识 |
| `REDIS_URL` | 私有 Redis 连接地址 |
| `WEIYU_MYSQL_*` | 微语数据库连接参数 |
| `DELIVERY_DB_PATH` | 任务数据库，默认 `.runtime/delivery.sqlite3` |
| `WX_MEDIA_HOSTS` | 可选，额外允许的微信图片域名，逗号分隔 |
| `WEIYU_MEDIA_ORIGINS` | 可选，允许的微语媒体源，逗号分隔 |
| `IMAGE_MAX_BYTES` | 单张图片上限，最大 30 MiB |
| `LOG_LEVEL` | 日志级别，默认 `INFO` |

仅允许可信媒体域名，不将数据库、Redis 或管理后台直接暴露到公网。

## 数据与当前限制

- `.env`、`.runtime/`、Redis/微语数据库、图片和生产日志属于部署私有数据，不应提交、上传为 Issue 附件或打包发布。SQLite 任务内会保存消息和媒体地址。
- 运行日志可能包含店铺、用户或会话标识，异常信息也可能携带请求地址；生产日志应限制访问并脱敏，禁止公开原始日志。
- 当前代码不包含客户资料、订单、物流或售后的完整只读查询集成。
- 微语撤回不等于微信撤回；尚未发送的消息可取消，已提交或结果未知的消息需按实际状态处理。
- 消息发送受平台权限、会话时限和配额约束；本地测试通过不代表实际平台联调通过。
